# Лабораторная работа №5. Реализация клиентской логики

**Модуль:** Разработка web приложений
**Тема:** Современная разработка веб-приложений
**Предметная область:** Система бронирования рабочих мест (Вариант 11) — сотрудники бронируют рабочие места в офисе на определённую дату.

## Цель работы

Научиться писать клиентскую часть веб-страницы: обрабатывать действия пользователя, менять содержимое страницы через JavaScript и получать данные с сервера асинхронными запросами. Делала на примере своей темы — бронирования рабочих мест.

## Что получилось

Страница `src/index.html` показывает список броней и форму, через которую можно добавить новую бронь. Вся логика — в `src/js/app.js`. Данные берутся не с настоящего сервера, а из учебного mock-сервера (`src/js/mock-data.js` и `src/js/mock-api.js`), который ведёт себя как обычный API:

- `GET /api/bookings` — отдаёт список броней, можно отфильтровать по статусу (`status`) и найти по тексту (`q`);
- `GET /api/employees` — список сотрудников (вторая сущность, для расширения в будущем).

У каждой брони есть: `place` — место (например, «A-12»), `employee` — сотрудник, `date` — дата, `status` — статус (`booked`/`free`/`cancelled`), `location` — этаж.

## Обработка событий

| Событие | Где | Функция | Что делает |
| --- | --- | --- | --- |
| `submit` | форма «Новая бронь» | `onFormSubmit` | проверяет название места, добавляет бронь в начало списка |
| `click` | кнопка «Загрузить с сервера» | `refreshList` | запрашивает список броней |
| `change` | фильтр по статусу | `refreshList` | обновляет список под выбранный статус |
| `input` | поле поиска | `refreshList` | обновляет список при каждой букве |
| `click` | кнопка «Отменить/Восстановить» | `onDoneClick` | меняет статус брони прямо в таблице |
| `click` | кнопка «Удалить» | `onDeleteClick` | спрашивает подтверждение и убирает строку |

В обработчике формы стоит `event.preventDefault()`, чтобы страница не перезагружалась. Если название места короче 3 символов, под полем появляется красная подсказка и бронь не добавляется.

## DOM и запросы к серверу

- Новые строки таблицы создаются через `document.createElement`, текст в ячейки записывается через `textContent` (не `innerHTML`, чтобы не было XSS).
- Удаление — `row.remove()`.
- У отменённой брони строка получает класс `done` (текст становится зачёркнутым), кнопка меняет подпись на «Восстановить».
- Функция `loadTasks()` собирает адрес вида `/api/bookings?status=...&q=...`, делает `fetch`, проверяет `response.ok` и возвращает JSON.
- Функция `refreshList()` оборачивает это в `try/catch/finally`: показывает «Загрузка…», блокирует кнопку, а если ошибка — выводит сообщение (отдельно обработала случай «нет сети»).

## Состояния страницы

Предусмотрела четыре состояния: загрузка, список получен, список пустой, ошибка — всё показывается в блоке `#info`.

## Вывод

Получилось реализовать всё, что требовалось: обработку событий (форма, кнопки, фильтр, поиск), изменение страницы через DOM без перезагрузки (добавление и удаление строк, смена текста, атрибутов и классов) и загрузку данных через `fetch` с обработкой загрузки, пустого результата и ошибок. Если в следующей лабораторной появится настоящий backend, менять в коде нужно будет только адрес запроса — сама логика останется прежней.
